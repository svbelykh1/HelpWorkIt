PHP в режиме CGI (Common Gateway Interface) — это режим работы интерпретатора PHP, при котором веб-сервер запускает PHP-скрипт как отдельную программу.
 
	CGI — стандартный протокол, который позволяет веб-серверу запускать внешние программы (CGI-скрипты) для обработки пользовательских запросов и генерации
	динамического содержимого. 
	PHP работает как отдельный процесс, который запускается каждый раз, когда запрашивается страница.
	Передача данных между веб-сервером и PHP происходит через переменные окружения и (для некоторых типов запросов, например POST/PUT) через стандартные потоки ввода-вывода.
	 
	Алгоритм работы:
	Веб-сервер получает HTTP-запрос.
	Определяется необходимость запуска PHP-скрипта. 
	Если запрашиваемый ресурс должен быть обработан PHP-скриптом, веб-сервер передаёт запрос через интерфейс CGI к исполнимому файлу php-cgi (интерпретатору).
	Передача данных запроса и запуск скрипта. 
	Веб-сервер устанавливает ряд переменных окружения перед тем, как запустить CGI-скрипт, которые содержат информацию о запросе и сервере. 
	PHP-скрипт может получить доступ к этим переменным через суперглобальный массив $_SERVER в PHP.
	Формирование ответа. PHP-скрипт генерирует ответ, который может включать HTML-код, заголовки ответа и другие данные. Выходной поток отправляется обратно веб-серверу 
	через стандартный вывод (STDOUT).
	Веб-сервер отправляет ответ пользователю. Веб-сервер получает данные от CGI и отправляет их в браузер пользователя как ответ на исходный запрос.
	 
	Конфигурация
	Переключить PHP в режим CGI можно двумя способами:
	Автоматически — в панели управления хостингом для каждого домена доступна настройка php.ini, 
	режим работы PHP автоматически переводится в режим CGI при добавлении хотя бы одной опции php.ini в «Стандартном», «Ограниченном» или «Параноидальном» режиме.
	Вручную — можно создать файл php.cgi, закачить его на сервер в ASCII-режиме в папку домена, на котором предполагается запускать PHP в режиме CGI, 
	и установить на файл права 0755 (rwxr-xr-x).
	 
	Важно: PHP в режиме CGI автоматически подключается только для основного домена, для поддоменов — вручную. 

	Недостатки
	Низкая производительность при высокой нагрузке, так как для каждого запроса CGI запускает новый процесс сервера.
	Проблемы с авторизацией средствами PHP (например, с помощью команды Header) — скрипт получает не все необходимые серверные переменные

PHP в режиме FastCGI

	Помимо CGI режима, PHP из коробки умеет работать и в FastCGI режиме (с версии 5.3 даже в двух FastCGI режимах). 
	Режим включается флагом при компиляции интерпретатора, флаг зависит от версии PHP.
	Для работы с Apache нужен модуль mod_fcgid или mod_fastcgi, либо связка из mod_proxy_fcgi + PHP-FPM.
	Nginx умеет работать с FastCGI приложениями из коробки, но именно для PHP дополнительно нужен PHP-FPM (см. ниже).
	Следует помнить, что при работе PHP в режиме FastCGI в памяти висит сам php интерпретатор, а не какой-то конкретный php-скрипт.

PHP-FPM
	FastCGI Process Manager, "Менеджер процессов FastCGI". Это альтернативная реализация FastCGI режима в PHP с несколькими дополнительными возможностями,
	которые обычно используются для высоконагруженных сайтов.
	Изначально PHP-FPM представлял из себя набор патчей от Андрея Нигматулина, которые устраняли ряд проблем,
	мешающих полноценно использовать PHP в режиме FastCGI (список улучшений). С версии PHP 5.3 набор патчей включён в ядро,
	а дополнительные возможности PHP-FPM включаются флагом при компиляции.
	PHP-FPM используется в основном в связке с Nginx, без установки Apache.
	
	Реальный пример работы PHP-FPM
	Представим, что в наше приложение одновременно приходит 50 клиентов. 
	Сначала они обращаются в наш NGINX, который по факту пробрасывает запросы сквозь себя на PHP-FPM (за исключением запросов за статическими ресурсами/файлами), 
	а дальше PHP-FPM пытается обработать все запросы с помощью своих процессов (воркеров).
	Допустим у нас запущено 5 воркеров. В таком случае во время одновременного запроса первые 5 клиентов будут обрабатываться сразу, 
	а остальные 45 становятся в очередь и ждут, когда первые 5 закончат обработку. PHP-FPM позволяет задавать настройки в зависимости от ваших потребностей, 
	будь то динамическое увеличение воркеров для того чтобы клиенты не ждали в очереди 
	или экономия ресурсов с целью ускорения обработки запросов со статическим количеством воркеров.

mod_php
	Это модуль для Apache, позволяющий ему выполнять php скрипты. Является наверно самым популярным и простым способом подружить Apache и PHP. 
	Модуль не использует ни CGI, ни FastCGI. 
	Есть свои минусы — скрипты выполняются под пользователем веб-сервера, невозможно использовать больше одной версии PHP.
